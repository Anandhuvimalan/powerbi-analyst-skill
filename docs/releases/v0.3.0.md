# v0.3.0 — Authored canvases, no silent report template

Earlier versions described an agent-driven design workflow but still defaulted
to a preset report and injected a fixed header, navigation strip and card styles
while rendering. That limited how much the agent could change the experience.

The agent now owns the full composition. The PBIR writer emits exactly its
authored elements and native formatting, with no automatic title, navigation,
KPI row or visual arrangement. Plans can set canvas dimensions, typography,
page backgrounds, layering and reading order. The AI provider receives source
profiles, business context and a model scaffold without a report template.
The original advanced DAX, M and modeling references are preserved.

## Migration

- `build` defaults to agent mode. Supply an analysis brief, model plan and report
  plan, or configure `reasoning.command`. A capable host agent authors these;
  the package does not bundle an LLM or credentials.
- `plan` writes profiles, a model scaffold and `design-context.json`. It does not
  create or overwrite an authored report plan.
- For preset connectivity demos only, use `--bootstrap` or `agent_mode:false`.
  `plan --bootstrap` writes a separately named `bootstrap-report-plan.json`.
- Add visible headings/navigation explicitly to older custom plans that relied
  on the renderer inserting them. Author formatting through the theme and native
  visual objects. See `references/project-design.md` inside the skill.
- Download the updated skill ZIP and rerun its setup helper. Old installed copies
  do not receive source changes automatically.

## Validation

60 tests pass, including exact element/geometry preservation, absence of injected
navigation on multi-page reports, compact authored cards, background layering,
default-mode enforcement and template-free reasoning input. Two reports built
from the same small test dataset use different canvas dimensions, reading order,
visual counts and placement. Both pass Microsoft's installed report-authoring
CLI and official remote PBIR schemas.

These checks demonstrate execution fidelity and structural validity. They do not
establish visual polish or analytical originality. These two new test reports
have not been refreshed or visually reviewed in Desktop. Design quality depends
on the host agent's analysis and rendered review; changing colors or positions
alone is not treated as proof of a better dashboard.
